# Cookbook

One task per recipe: the program (or the commands) and what it prints. Every program is in `docs/examples/src/`, and
its output here is regenerated by `fobis rule --ex docs-examples`.

## Coefficients and distributions

$Z_i$ enters only through the ratio of electron–electron to electron–ion collisions. At $Z_i \to \infty$ the
electron–electron terms vanish and the coefficients tend to the exact Lorentz-gas values; at $Z_i = 1$ they are those
of Epperlein and Haines (1986).

### The electron f₁ itself

`response` returns moments; to look at $f_1(u)$, build the source and call `solve` directly. `source_fast_flux`,
`source_electric` and `source_thermal` are the three drives, each on the full grid:

<<< @/examples/snippets/cb_f1.F90{fortran}

<<< @/examples/output/cb_f1.txt{text}

`solve` accepts several right-hand sides as the columns of `rhs` and returns $f_1$ on the full grid, with the boundary
conditions applied ($f_1(u_1) = f_1(u_2)$, $f_1(u_N) = 0$). `moment(f1, p)` is $\int_0^{u_{\max}} u^p f_1\,du$ by Simpson's
rule; the fast-ion closure is $j^\nu = 1 - 4\pi M_3/(Z_\alpha u_{\text{flux}})$ and $\zeta^\nu = 4\pi M_5/u_{\text{flux}}$.

### Check grid convergence

<<< @/examples/snippets/cb_convergence.F90{fortran}

<<< @/examples/output/cb_convergence.txt{text}

The error falls by about 4 per doubling: second-order convergence, thanks to the node aligned with $u_\alpha$. The
default 401 nodes are accurate to $2\times10^{-4}$. For $u_\alpha < 4h$ (below $v_\alpha/v_{Te} = 0.07$ on the default
grid) `init` stops: refine the grid.

## Fast ions

### A fast-ion species the fits do not cover

The algebraic fits cover α particles in DT only; the kinetic solver takes any species. A 200 MeV carbon beam (Sec. V B
of the paper) at 1–10 keV:

<<< @/examples/snippets/cb_other_species.F90{fortran}

<<< @/examples/output/cb_other_species.txt{text}

When the fast ions are faster than the electrons, $f_1$ extends further: widen the grid (`u_max`) with the speed. The
current ratio collapses towards zero there — the reason the paper's blanket $j^0_{e\alpha} \approx -5j^0_\alpha$
overestimates the low-temperature end of its carbon-beam estimate ([Findings and errata](/guide/errata)).

### An isotropic population: the conventional coefficients change

Only the isotropic part $F_0$ enters the operator; with `u_a` > 0 and `n_ratio` > 0 it modifies the conventional
coefficients (the paper's Sec. VI and Fig. 6):

<<< @/examples/snippets/cb_isotropic.F90{fortran}

<<< @/examples/output/cb_isotropic.txt{text}

Below $n_\alpha/n_e = 10^{-3}$ the effect is below 0.25%: the paper's assumption $n_\alpha \ll n_e$ holds.

### Your own fast-ion spectrum

Any pure function of the `speed_distribution` interface, `f(u, p)`, can describe the fast ions. Put it in a module (a
module procedure, not an internal one: no host association is needed, because the parameters travel in `p`):

<<< @/examples/snippets/cb_custom_spectrum.F90{fortran}

<<< @/examples/output/cb_custom_spectrum.txt{text}

The distribution may have any normalisation (it is normalised to unit density on the grid) and must vanish well before
`u_max`. It must be resolved by the grid: a feature narrower than a few cells needs more nodes. Check with a convergence
run as above.

### An electron f₀ from a table {#an-electron-f0-from-a-table}

A distribution computed elsewhere, for example by INDACO, enters as a two-column table: $u_L = p/\sqrt{m_eT_e}$ and
$f_0$, with any normalisation and `#` comments allowed. `read_table` reads it and `electron_table_params` packs it
(a spline of $\ln f$) for `electron_table`:

<<< @/examples/snippets/cb_electron_table-table.F90{fortran}

<<< @/examples/output/cb_electron_table.txt{text}

The table must start at $u_L = 0$, increase strictly and be positive. Beyond its last row $\ln f$ continues linearly,
so the table must already decay there (`init` stops if $f_0$ does not vanish at `u_max`). Rows a few hundredths of
$\sqrt{m_eT_e}$ apart resolve a Maxwellian to $10^{-9}$. The driver does the same from the command line:
`./bin/appelbe_electrons f0.dat` writes `results/electrons_table_{profile,f1}.dat` and prints the TS and ECE readouts
and the transport changes ([Non-Maxwellian electrons](/guide/electrons)).

## The reproduction

### Reproduce the paper's figures

```bash
fobis build --mode gnu
fobis rule --ex figures          # every bin/appelbe_* -> results/*.dat, previews results/*.png (about 4 minutes)
fobis rule --ex report           # report/appelbe_report.pdf
```

### Compute the way the paper did

```fortran
par%n_ratio = paper_n_ratio      ! the paper's isotropic alpha population, n_a/n_e = 1e-3
call init_paper(op, par)         ! the paper's grid: 199 nodes on [0, 5], no node on u_a
r = op%response(omega_tau=0._R8P)
```

See [7. The paper, number by number](./tutorial/07-paper) and [The paper's set-up](/guide/paper-setup). Use it to
compare with the paper, never for physics.

### Refresh the curves extracted from the paper

The paper (and, for the Epperlein–Haines cross-check, the accepted manuscript of Davies et al. 2021) must be in
`references/`, which is git-ignored:

```bash
python3 scripts/digitize_paper.py     # report/data/*.dat, read from the vector graphics with mutool
```

### Add a driver

A driver is a program `src/app/appelbe_<name>.F90` that writes `results/<name>.dat` with `open_results` (one `#` header
line). `fobis build --mode gnu` builds it, `fobis rule --ex figures` runs every `bin/appelbe_*`. Add its comparison to
`scripts/report_numbers.py` and its figure to `report/appelbe_report.tex` ([Report pipeline](/guide/report)).

### Run with runtime checks

```bash
fobis build --mode gnu-debug          # bounds, NaN initialisation, FP traps (invalid, zero, overflow)
fobis rule --ex tests
```

Code that may overflow in release mode harmlessly (an `exp` of a large argument) traps here: keep it overflow-safe.
